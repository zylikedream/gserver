# ADR 0013: 失败语义与可观测性

- 日期：2026-09-16（2026-09-18 接受，拆分并精简）
- 状态：**Accepted**
- 关联：ADR 0008、ADR 0012

## 背景

失败来源分属不同层次：所有权丢失、状态加载失败、业务规则拒绝。调用方与运维对它们的需要完全不同——调用方只能决策"重试还是放弃"，运维才需要确切原因。

同时，追踪、指标、日志、定时这四类遥测在新运行时都有内置接口，需要决定是接过去还是继续自建。

## 决策

### 1. 失败原因分层

- **详细失败原因只进日志与指标**，不跨进程传给调用方（原因：跨节点传递细粒度原因需要协议支持，且没有消费方）。
- **调用方按错误类型决策**，不按原因：可重试类（进程未知、连接不可达）→ 服务端重试；否则失败。
- **业务失败不受影响**，仍走响应消息通道返回（不变量 9）。
- 不建墓碑，不做激活前预检。

### 2. 遥测接口收敛到现有出口

- **追踪**：实现运行时的追踪适配器，把其追踪数据转成现有链路追踪数据送入既有导出器；删除门面中手写的传播代码。业务侧的跨进程链路因此闭合。
- **指标**：把运行时指标并入现有的单一指标端点，对外端点与探针不变。
- **日志**：实现运行时的日志适配器，替换旧的适配层；日志主体与业务调用点不变。
- **定时**：调度语义保留在应用层，定时实现交给运行时。

### 3. 异常级别不得触发进程退出

运行时的"捕获到 panic"级别表示**框架已捕获该异常、节点继续运行**，它**不得**映射到会导致进程退出的日志级别。映射错误会让单个 actor 的 panic 终止整个进程。

### 4. 日志双写

必须显式关闭运行时的默认日志输出，否则它与现有日志出口重复输出。

## 理由

失败原因跨进程传递的成本（协议扩展、跨节点错误标识、消费方）远高于收益：调用方需要的是可否重试，运维需要的是确切原因，而后者只需要本地可达。这是 ADR 0006 已确立的分工，本次迁移沿用而非改变。

遥测自建部分的价值随运行时提供原生能力而消失；保留两套只会让链路断裂与指标重复。

## 考虑过的方案

**把详细失败原因跨进程传给调用方**：需要协议扩展与跨节点错误标识，且没有消费方——调用方只需要知道能否重试。拒绝。

**为异步初始化失败建墓碑**：引入额外状态与过期清理，而调用方本就无法处理每一种底层失败原因。拒绝。

**继续自建追踪、日志、指标适配，不接运行时原生接口**：会保留两套链路与重复输出，且跨进程链路仍然断裂。拒绝。

## 后果

- 跨进程错误身份不再承载业务语义，排障依赖日志与指标关联。
- 追踪链路闭合后，原先因手写传播而断裂的跨 actor 链路可直接观测。
- 定时器生命周期与进程绑定，进程终止即失效。

## 推翻条件

- 追踪适配后跨节点链路仍无法闭合，或控制面/事件路径的缺失导致排障不可接受（注意：部分控制面与定时投递本就不被追踪，不能据此判定消息未送达）；
- 合并指标后出现端点冲突或采集侧不兼容；
- "原因只进日志"导致线上定位成本显著上升，需要向调用方透出部分原因。
