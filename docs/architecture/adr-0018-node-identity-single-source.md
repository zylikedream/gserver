# ADR 0018: 节点身份只有一个来源

- 日期：2026-09-21
- 状态：**Accepted**
- 关联：ADR 0010（细化其"路由身份"取哪个值）、ADR 0011
- **不触碰** `invariants.md` 中的条目：身份分层与租约判据不变，改变的是路由身份这个值从哪来。

## 背景

ADR 0010 要求路由身份是**稳定的、可寻址的节点名**，并且点名它同时用于**运行时路由**与**服务发现**，两者必须一致。

实现上，这个"节点名"在项目里被构造了两次：

- 一处由配置里的能力名与监听主机拼出；
- 一处由部署给出的实例名（含实例区分度的那一段）与监听主机拼出。

两处在本地与测试环境**恒等**——因为实例名恰好等于能力名。只有部署环境给出带后缀的实例名（编排器按序号或随机串命名实例）时，两者才分叉。

分叉的后果不是"某个调用失败"，而是**节点认不出自己**：服务目录里记的是一个名字，运行时自报的是另一个名字，于是"候选节点是不是本节点"这个判断恒为否——本该就地创建的操作被当成跨节点请求发给自己，激活随之失败。

## 决策

**节点身份只从一个来源取得：部署给出的实例名（含实例区分度的那一段）。** 运行时路由、所有权记录、服务发现、以及以节点身份为键的其它用途，全部使用这一个值。

配置里的能力名保留，但**只作标识用途**（日志里说明这是哪一类节点），不再参与节点身份的构造。

## 理由

- **三处一致只能靠单一来源保证。** 两个地方各自拼同一个语义的值，一致性就只能"碰巧成立"，而 ADR 0010 的这条要求恰恰是"必须一致"。重复构造让要求变成运气。
- **实例名自带区分度，消除 ADR 0010 记录的一个推翻条件。** ADR 0010 的推翻条件之一是"稳定节点名在真实部署下产生冲突（例如同主机多实例）"；以实例名为身份时，同一主机上的多个同类实例天然可分。
- **所有权身份不受影响。** 每实例随机令牌仍承担实例唯一性（ADR 0010），路由身份不需要为它负责，因此带上实例区分度不会让所有权判据错位。
- **能力名不必从节点名推导。** 承载能力的节点是靠服务目录登记的，不是靠解析节点名的前缀；先前把"前缀即能力名"当作约定，但实际没有消费者依赖它。

## 考虑过的方案

**全部改用配置里的能力名（去掉实例区分度）。** 能让三处一致，但会把 ADR 0010 已经记录的"同主机多实例冲突"坐实，并丢失部署层给出的实例区分度。拒绝。

**保留两处构造，只把分叉处对齐。** 治标：一致性仍然依赖"两个地方记得写同一个式子"，下一次改动可以再次漂移。拒绝。

## 后果

- 节点名变长，且包含部署层的命名（含连字符与序号），日志与监控里读到的节点名随之变化。
- 节点名在**部署环境下**随实例更替而变：按固定序号命名的实例保持不变；按随机串命名的实例每次都变。
  - 前者（承载实体的那类）不受影响。
  - 后者（不承载实体、不参与所有权的节点）名字变化只影响它自己的对外身份，而它持有的会话类实例本就随进程消失，因此影响面是陈留记录的自愈路径。
- 以节点身份为键的租约因此按实例隔离：同一节点名的新旧实例不再竞争同一条租约记录，快速重启不再需要等待租约过期。
- 服务发现与运行时路由共用同一个值，"候选节点是否为本节点"的判断回到恒等。

## 推翻条件

- 部署环境的实例名不稳定，且由此产生的陈旧记录与重连开销被实测证明不可接受；
- 出现依赖"节点名前缀即能力名"的消费者。
