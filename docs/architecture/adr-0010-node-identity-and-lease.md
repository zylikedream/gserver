# ADR 0010: 节点身份与节点租约

- 日期：2026-09-16（2026-09-18 接受，拆分并精简；2026-09-19 修正决策段残留的旧写法：唯一性来自每实例随机令牌，不是节点启动时刻）
- 状态：**Accepted**
- 关联：ADR 0006、ADR 0008、ADR 0012
- **取代**：ADR 0006 决策 3 中「节点实例名同时作为唯一进程身份和租约令牌」——本 ADR 将路由身份与所有权身份分离，令牌改为每实例随机。ADR 0006 的其余决策（Activation Directory、节点级 Lease、原子 Claim、PostgreSQL Fencing、CP 取舍、长期不建设 shard ownership）全部保留。

## 背景

当前的节点实例名同时承担三件事：可寻址的身份、所有权记录里的持有者标识、租约令牌。它带进程启动时间戳，因此同一地址重启会产生一个新名字。

新运行时需要一个稳定的、可解析的节点名（用于路由与发现）。把稳定名字直接当作所有权身份，就把"路由身份"和"所有权身份"合并成了同一个值——而所有权机制要求持有者身份在每次实例更替后都不同。

## 决策

本 ADR 触碰 `invariants.md` **#1（单写者）**：其判别键的唯一性由本 ADR 决策的所有权身份承担；
以及 **#5（身份分层）**、**#6（租约不可静默抢占）**。

- **路由身份**：稳定、可寻址的节点名，供运行时路由与服务发现使用。
- **所有权身份**：不依赖路由身份提供唯一性。所有权身份 = 路由节点名 + 每实例随机的令牌，使同一节点名在不同实例之间仍有不同身份。

**租约获取保持"失败即启动失败"**（对应不变量 6）：节点租约以"仅当不存在时写入"获取，而不是无条件覆盖。

**租约心跳保持进程内普通循环**，不做成 actor。

## 理由

**为什么不无条件覆盖租约**：覆盖会让新进程静默夺走仍在运行的旧进程的租约。旧进程要等到下一个心跳才发现自己已失去租约，其间新旧进程对同一批所有权记录会用不同判断，旧进程最后一次落库会被数据库 fencing 拒绝——这是确定性的数据丢失，而不是可自愈的竞态。
代价是：同一地址上的容器重启若落在租约有效期内，启动会失败并等待租约过期（编排器重试可吸收）。地址变化的重启不受影响。

**为什么租约心跳不做成 actor**：自终止是节点级决策且要求即时，而 actor 内的停止是异步的，达不到即时；续约是阻塞 I/O，放进 actor 会让租约到期检查排队迟到，削弱"续约卡住时按截止时间自终止"的保障。

**为什么令牌必须每实例随机**：租约过期后新实例接管时，只有令牌不同才能正确区分新旧持有者，并让旧实例的续约失败从而自终止。

## 考虑过的方案

**稳定节点名 + 无条件覆盖租约**：见上，会引入静默抢占窗口，拒绝。

**租约心跳 actor 化**：见上，无收益且削弱保障，拒绝。

**用运行时提供的实例代号（节点启动时刻）承担唯一性**：精度为秒级，同一秒内的重启会碰撞，而随机令牌不碰撞亦不需额外精度取舍。拒绝。

**让世代严格递增承担全部唯一性**：可行，但要求数据库 fencing 放弃同世代幂等分支，并把同世代重复推进从"合法"改为"失败"。既然身份中已有每实例唯一分量，这样做是多余的，拒绝。

## 后果

- 节点名稳定，路由与发现可依赖它。
- 所有权身份携带每实例随机分量，数据库 fencing 的判别无需改动。

## 推翻条件

- 实测表明同地址重启等待租约过期影响可用性，且无法由编排器重试策略吸收；
- 稳定节点名在真实部署下产生冲突（例如同主机多实例）。
