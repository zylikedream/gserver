# ADR 0020: 测试替身放在真实边界上

- 日期：2026-09-30
- 状态：**Accepted（执行中）** — 替身与首个使用点已落地；其余跨服务调用按需接入
- 关联：ADR 0001（依赖注入取代全局单例）
- 触碰不变量：无（本文只决定测试替身的位置，不改变任何生产行为要求）

## 背景

ADR 0001 定了"不用 gomonkey、用可注入的依赖替身"，并明确可替换函数变量**只能作辅助**。但落地时它退化成了默认手段：仓库里曾有 5 处包级可替换函数变量，其中 3 处没有任何生产写入方，纯粹为了测试能观察或替换。

这批接缝有共同形状：把一个普通调用包成可替换变量，测试把变量换成假实现。它的代价不是行数，是**可漂移**——替身锁住的是 Go 函数签名，对端契约改了它照样绿。

## 观察

`friend_relation` 表由 friend 应用持有（`src/apps/friend/logic/model.go`）。role 侧却有两条问"两人是否好友"的路径：一条经 friend 服务接口（`role_friend.go` 的 `getRelation`），一条直查该表（`isFriend`）。后者正是被包成可替换变量的那个。

这不是孤例。凡是跨服务调用，当前都没有替身位置，测试只能把接缝往业务代码里推。

## 成因

**真正的 I/O 边界是服务到服务调用，那一层没有替身。** 于是替身逐层上移，最终落在业务函数上，并按应用逐个重新发明一次。

仓库两端都有路：`make e2e` 跑真依赖（最外），actor 测试有真实运行时与真实进程（`gxyactortest`）。中间这段——服务到服务调用——是空的。

## 决策方向

**替身放在真实边界上，不放在边界之内。** HTTP 调用的替身是"对面那个服务"，不是"调用它那个函数"。

与 `gxyactortest` 同一形态：保留真的边界（真服务器、真服务发现），只把"对面是谁"换成假的。生产代码因此不需要为测试留任何位置。

## 理由

- **契约会红。** 替身按服务的路由与响应体说话，对端契约漂移时测试失败；按函数签名说话的替身不会。
- **替身停止扩散。** 一次投入，全部跨服务调用受益；per-app 接缝每新增一处调用就要新增一处。
- **与已有实践同形。** actor 侧已经这么做，HTTP 侧只是补上缺的那一半。

## 考虑过的方案

**每个应用各自 mock 自己的逻辑。** 拒绝。理由如上：可漂移，且随调用点数量线性增长。

**在 HTTP 客户端装假传输层，绕开服务器。** 保留。更省，但会跳过 URL 拼接、状态码判定这些中间步骤——那些正是要测的东西。落地时若发现真服务器过重，可作为退路。

**继续用包级可替换函数变量。** 已在此前几轮清理中从 gateway 移除，不再作为选项。

## 现状

gateway 侧的接缝已清理完毕。跨服务调用的替身已落地，首个使用点是 role 侧问「两人是否好友」的那条经 friend 服务的路径——该文件此前零测试。

替身一下来就兑现了它的理由：**契约缺陷被抓到，而且此前所有测试与增量回归都是绿的。** 批量接口的数组参数在调用方的编码方式下根本绑不进服务端类型，三条批量路径的入参恒为空；调用方又在结果为空时提前返回成功，于是整条链路静默无效。假函数形态的替身不会红在这里——它锁的是函数签名，不是参数怎么过线。

`isFriend` 的越界直查仍未处理——它是 role 侧唯一一处跨应用读表，改动涉及 friend 服务的可用性成为 steal 与私聊准入的运行时依赖，属于独立决策。

guild 侧读 role 数据是**同一类问题**（跨应用直读对方的表），已与上面这条**合并另议**：它在测试接缝门禁的基线里保留一条，门禁只冻结存量、不再新增。
