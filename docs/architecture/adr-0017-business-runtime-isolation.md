# ADR 0017: 业务对象与运行时之间的隔离

- 日期：2026-09-21
- 状态：**Accepted**
- 关联：ADR 0008、ADR 0014（**取代**）、ADR 0015（保留）、ADR 0016（目标由本形态达成）
- 触碰不变量：#3、#4（要求不变，承载位置在门面内移动；见 `invariants.md`）

## 背景

ADR 0014 定的形态是：业务结构体直接内嵌门面基类，而该基类内嵌运行时的行为基类，业务覆写运行时回调时显式调回基类。

当时拒绝"业务侧接口 + 适配层"的理由是：适配层不含行为，只把一次调用换成另一次调用。

**这条理由不成立。** 适配层承载的是**编排**：初始化段与异步段的衔接、分派目标的注册时机、跨节点消息的还原、定时消息与业务消息的分流。在 ADR 0014 的形态下，这段编排没有消失，而是落到了**每个业务 actor 里**——每个 actor 各自记得在初始化末尾驱动异步段、各自记得在业务入口里把机制消息转回基类。凡是"忘了就静默失效"的编排，都会在某个 actor 里被忘掉。

同时，内嵌运行时行为基类的实际后果比当时预期的严重：运行时行为基类内嵌运行时的**进程接口**，其全部方法随内嵌提升到业务对象上。业务因此能：

- 直接调用运行时的原生发送，绕过门面的跨节点封装；
- 覆写运行时的业务回调，把门面的机制一起关掉——ADR 0016 想禁止的行为，在该形态下只是"目前没人这么写"。

两者都不是靠文档能禁止的，因为它们是内嵌提升的直接结果。

## 决策

**业务对象不内嵌任何运行时类型。** 门面在业务与运行时之间放一个只面向运行时的适配对象：运行时只看得见它，业务只看得见门面。

由此，**编排归门面**：初始化段与异步段的衔接由门面驱动，业务只声明异步段做什么。

## 理由

- **正确性靠类型，不靠约定。** 隔离之后，"业务对象被当作运行时行为对象交给运行时"在编译期不成立，而不是靠"别那么写"。ADR 0016 的目标（业务不可能覆写掉门面机制）到此才真正达成；此前它只是命名上的约定。
- **编排只有一处。** 异步段的驱动、分派目标的注册、机制消息的分流都在门面内，业务侧没有"必须记得调用基类"的步骤。
- **业务侧不再依赖运行时**，更换运行时的触碰面回到门面——这是 ADR 0008 的原意，此前被 ADR 0014 收窄了。
- **门面成为唯一的能力入口**：跨节点封装无法被绕过，因为业务拿不到运行时的原生发送。
- **分层维度是"是否承载实体"，不是"需要哪些能力"**：按消息类型分派属于"是个 actor"，与所有权无关——不承载实体的 actor 一样可以把消息路由到方法。把它绑在承载实体那一层，会让协调者这类 actor 只能靠手写类型分支来路由。

## 考虑过的方案

**保持 ADR 0014 的形态，只在门面内收窄。** 无法阻止业务覆写运行时回调，也无法阻止业务直接调用运行时原生方法——两者都是内嵌提升的结果，只能靠文档与纪律约束。拒绝。

**运行时中立化**：门面自定义身份与上下文抽象，使运行时可以整体替换。迁移已经完成，没有第二个运行时；抽象的成本是实打实的（身份要靠形状猜测来源、每个能力都要在抽象上开一次口），收益是假设性的。拒绝。运行时类型留在门面**内部**即可，不必再抽象一层。

## 后果

- 业务侧不出现运行时类型：业务入口签名、消息类型、进程标识都由门面给出。
- 业务的对象类型不再满足运行时的行为契约，因此**不可能被直接登记**；登记的产物是门面持有的适配对象。
- 门面必须自己实现运行时的行为契约（可由内嵌运行时的行为基类承担，该内嵌不外露）。
- 监视通知等运行时事件由门面翻译后交给业务，不再以运行时消息类型出现。
- 业务侧不再有"必须调回基类"的初始化约定；取而代之的是门面按需发现业务实现了哪些入口。
- 门面内嵌运行时的行为基类仍然存在，因此更换运行时依然要改门面——隔离的是**业务**，不是门面自身。

## 推翻条件

- 需要在不触碰门面的前提下支持第二个运行时——本形态要求门面内嵌某个运行时的行为基类；
- 门面的转发面退化为纯转发、不再承载编排与策略——那时隔离只剩形式，不如取消。
